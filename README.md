# Wolffe TV v4 Alpha 3.7

A native macOS controller for Roku TVs on your local network. Wolffe TV can discover Roku televisions automatically, remember multiple TVs, detect physical TV inputs, customize those input tiles, and provide an in-window remote.

## What Wolffe TV does

Current Alpha 3.7 functionality includes:

- Automatic Roku discovery on the local network.
- Manual IPv4 entry if discovery is unavailable.
- First-launch Local Network onboarding.
- Multiple saved Roku TVs with a TV selector.
- Connectivity status and a Test Connection button.
- Automatic detection of physical Roku TV inputs.
- Custom names for detected inputs.
- Show/hide controls for individual inputs.
- Input reordering.
- Per-input icon and accent-color selection.
- Persistent per-TV input customizations.
- An in-window remote with Home, directional navigation, OK, Back, Play/Pause, Options, volume, mute, replay, power on, and power off.
- Universal macOS build output containing both Apple Silicon (`arm64`) and Intel (`x86_64`) architectures.
- A drag-to-Applications DMG generated by the included build script.

Wolffe TV communicates with Roku devices over Roku's External Control Protocol (ECP). Roku documents ECP as a local-area-network API and documents SSDP discovery for Roku ECP devices. The SSDP multicast endpoint is `239.255.255.250:1900`, and discovered Roku ECP services are normally available on port `8060`.

## Requirements

### Mac

The current project declares:

- **macOS 13 or later**
- **Swift tools 5.9**
- Universal output for **Apple Silicon and Intel Macs**

To build the app yourself, install full **Xcode** rather than relying only on Command Line Tools. The build script also checks for the macOS tools it uses before starting.

### Roku TV

For normal remote-control commands, Roku's current ECP documentation says **Control by mobile apps** must be enabled on Roku OS versions where that setting governs ECP key commands.

On the TV, look under:

**Settings → System → Advanced system settings → Control by mobile apps**

and make sure control is enabled if remote commands are not responding.

The Mac and Roku TV also need network connectivity to one another. Discovery additionally depends on local-network multicast traffic reaching the Roku devices.

# The easiest path: build and install

These instructions assume the source folder is in **Downloads** and is named:

```text
wolffe-tv-v4-alpha3.7-source
```

If your folder has a different name, substitute that exact name in the `cd` command.

## Step 1: Open Terminal

Open **Applications → Utilities → Terminal**.

Do not type the prompt characters shown by Terminal. Only paste the commands in the code blocks below.

## Step 2: Enter the source folder

```bash
cd ~/Downloads/wolffe-tv-v4-alpha3.7-source
```

If Terminal says the directory does not exist, check the extracted folder name in Finder and use that exact name.

## Step 3: Clear macOS quarantine from this source folder

Only do this for a source package you intentionally downloaded and trust.

```bash
xattr -dr com.apple.quarantine .
```

The final period means **the current folder**. Do not replace it with your entire Downloads folder.

## Step 4: Make the build script executable

```bash
chmod +x build-universal-dmg.sh
```

## Step 5: Build Wolffe TV

```bash
./build-universal-dmg.sh
```

The script performs a preflight check, builds a Release executable for `arm64` and `x86_64`, constructs the app bundle, generates the `.icns` app icon, ad-hoc signs and verifies the app, and creates the DMG.

A successful build ends with a `SUCCESS` section and reports the app and DMG locations.

The expected DMG is:

```text
build/Wolffe-TV-v4-alpha3.7-universal.dmg
```

## Step 6: Open the DMG

From the source folder in Finder:

1. Open `build`.
2. Double-click `Wolffe-TV-v4-alpha3.7-universal.dmg`.
3. Drag **Wolffe TV.app** to **Applications**.
4. Open Wolffe TV from Applications.

### Important signing note

The current build script uses ad-hoc code signing. The app is **not Developer ID signed or Apple-notarized** in this Alpha workflow. macOS may therefore apply additional security checks when you open it.

# First launch

Alpha 3.7 contains first-launch onboarding specifically for Local Network access and TV discovery.

## Step 1: Read the Local Network explanation

Wolffe TV explains that the app communicates directly with Roku TVs on your local network.

Click **Continue** when ready.

## Step 2: Allow Local Network access if macOS asks

Wolffe TV then performs its first discovery operation. macOS may display its own Local Network permission prompt.

If you want Wolffe TV to discover and control TVs on the network, choose **Allow**.

The permission dialog belongs to macOS. Wolffe TV cannot grant that permission to itself.

## Step 3: Review discovered TVs

Wolffe TV searches for Roku ECP devices and displays responding TVs with information including the device name, IP address, and model number when available.

For a TV not already stored in Wolffe TV, click **Add**.

If a discovered TV was already saved, Wolffe TV displays **Added** instead of creating a duplicate.

## Step 4: Continue

After adding the TVs you want, click **Continue**.

Wolffe TV remembers that onboarding has completed and normally opens directly to the dashboard on later launches.

# Adding TVs

## Automatic discovery

From the main dashboard:

1. Click **Add TV**.
2. Wait for the network search to finish.
3. Click **Add** beside the TV you want.
4. Click **Done** when finished.

Wolffe TV reports discovery diagnostics such as whether the probe was sent, how many replies arrived, how many valid Roku locations were found, and how many device-information responses loaded.

## Manual IP entry

If discovery does not find the TV:

1. Click **Add TV**.
2. Click **Enter IP Manually**.
3. Enter a friendly TV name.
4. Enter the TV's local IPv4 address.
5. Click **Save and Test**.

The app's manual-entry screen points to the Roku network information under:

**Settings → Network → About**

Example IPv4 format:

```text
192.168.1.25
```

Use the actual address shown by your television. Do not copy the example address unless it really is your TV's address.

# Using inputs

After a TV is selected, Wolffe TV can query the TV for its physical inputs.

If the dashboard says inputs have not been detected:

1. Make sure the TV is reachable.
2. Click **Detect Inputs**.
3. Wait for the input tiles to appear.

A detected tile can represent inputs such as HDMI, live TV/tuner, or AV depending on what the Roku TV reports.

Click an input tile to switch the selected TV to that input.

---

# Customizing inputs

Select the TV you want to modify first, because input customizations are stored with that TV.

Click **Customize Inputs**.

For each detected input you can:

### Rename it

Enter a custom display name in the name field.

Use **Restore Name** to return to the Roku-discovered name.

### Hide or show it

Use the **Visible** checkbox.

Hidden inputs remain stored but do not appear on the main input dashboard.

### Reorder it

Use the **up** and **down** arrow controls.

The chosen order is stored for that TV.

### Choose an icon

Use the Icon menu to select from the icon options provided by the app.

### Choose a color

Use the Color menu to select an input accent color.

### Preview the result

The editor displays a preview using the current name, icon, and color.

### Save the changes

Click **Done**.

The current implementation preserves the custom name, visibility, order, icon, and accent color when inputs are refreshed from the TV.

# Using the remote

Click **TV REMOTE** on the dashboard.

The Remote replaces the dashboard inside the same Wolffe TV window, so the main window remains resizable.

Current controls include:

- Home
- Up / Down / Left / Right
- OK / Select
- Back
- Play/Pause
- Options
- Volume Down
- Mute
- Volume Up
- Instant Replay
- Power On
- Power Off

Click **Back to Inputs** to return to the input dashboard.

If remote buttons do not affect the TV, see [Remote buttons do nothing](#remote-buttons-do-nothing).

# Managing multiple TVs

When more than one TV has been saved, use the TV selector near the top of the dashboard.

Changing the selected TV changes which device receives input and remote commands.

Input customizations are stored with each saved TV, so changing the name, icon, color, visibility, or order on one television should not apply those changes to another television.

## Editing a TV

1. Select the TV.
2. Click **Edit TV**.
3. Change the friendly name or IP address.
4. Click **Save and Test**.

## Removing a TV

1. Select the TV.
2. Click **Edit TV**.
3. Click **Delete TV**.
4. Confirm the deletion.

This removes the saved TV from Wolffe TV. The application does not reset the television itself.

# Troubleshooting

## The build says full Xcode is not selected

The build script expects the active developer directory to point inside the full Xcode application.

If Xcode is installed at `/Applications/Xcode.app`, run:

```bash
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
```

Then run the build script again:

```bash
./build-universal-dmg.sh
```

## `Permission denied` when starting the build script

Run:

```bash
chmod +x build-universal-dmg.sh
```

Then:

```bash
./build-universal-dmg.sh
```

## macOS blocks a downloaded source script

For this project's intentionally downloaded source folder, our development workflow clears quarantine only from the current project folder:

```bash
cd ~/Downloads/wolffe-tv-v4-alpha3.7-source
xattr -dr com.apple.quarantine .
```

Do **not** recursively remove quarantine from your entire Downloads directory.

## Wolffe TV finds no TVs

First check the diagnostics shown by the Add TV screen.

A successful discovery may show nonzero values for replies, Roku locations, and devices loaded. Zero replies alone does not prove that Local Network permission is denied. It can also mean no Roku responded to the discovery request.

Try these checks:

1. Confirm the TV and Mac have network connectivity to one another.
2. Make sure the TV is powered on far enough to answer network requests.
3. Click **Search Again**.
4. Check macOS Local Network privacy settings for Wolffe TV.
5. If discovery still fails, use **Enter IP Manually**.

Wolffe TV's onboarding also provides **Open Local Network Settings** when discovery cannot locate a TV.

## Checking Local Network permission manually

On current macOS versions that provide Local Network privacy controls:

**System Settings → Privacy & Security → Local Network**

Make sure Wolffe TV is allowed if you want it to communicate with local devices.

## Manual connection says the TV did not answer

Check:

- The IP address was typed correctly.
- The IP address still matches the TV's current address.
- The Mac can reach the TV on the local network.
- The TV is powered on / reachable.

You can edit the saved IP through **Edit TV**.

## Remote buttons do nothing

Roku's ECP documentation states that keypress commands require **Control by mobile apps** to be enabled on applicable Roku OS versions.

Check:

**Roku Settings → System → Advanced system settings → Control by mobile apps**

Also verify that Wolffe TV reports the selected TV as reachable.

## Inputs do not appear

1. Confirm the correct TV is selected.
2. Make sure the TV is reachable.
3. Click **Detect Inputs**, or open **Customize Inputs** and use **Refresh from TV**.

If the TV does not report a physical input that you expect, the current application only creates tiles from the physical input entries returned by the Roku query.

## An input will not switch

The current code maps Roku TV input IDs to supported Roku ECP key names for HDMI 1–4, AV, and tuner/live TV. An unrecognized input ID may be displayed without a working mapped key.

## Reset first-launch onboarding for testing

This removes only the onboarding-completed preference used by Alpha 3.7:

```bash
defaults delete com.wolffetv.app wolffeTV.hasCompletedOnboarding.v1 2>/dev/null || true
```

It does not intentionally delete the separately stored TV/device state.

# Building from source: every step

This is the full keyboard-monkey-friendly build sequence.

## 1. Install Xcode

Install the full Xcode application on the Mac.

After installing it, if the build script reports that full Xcode is not selected, run:

```bash
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
```

## 2. Extract the source ZIP

Extract the Wolffe TV source ZIP into Downloads.

Expected folder for this release:

```text
~/Downloads/wolffe-tv-v4-alpha3.7-source
```

## 3. Open Terminal

Open:

**Applications → Utilities → Terminal**

## 4. Move Terminal into the source folder

```bash
cd ~/Downloads/wolffe-tv-v4-alpha3.7-source
```

Optional sanity check:

```bash
pwd
```

The output should end in:

```text
/Downloads/wolffe-tv-v4-alpha3.7-source
```

List the important project files:

```bash
ls
```

You should see files including:

```text
Package.swift
Info.plist
AppIcon-source.png
build-universal-dmg.sh
Sources
```

## 5. Clear quarantine from this project folder

```bash
xattr -dr com.apple.quarantine .
```

## 6. Make the build script executable

```bash
chmod +x build-universal-dmg.sh
```

## 7. Build

```bash
./build-universal-dmg.sh
```

The script stops if a required preflight item is missing.

When successful, it prints `SUCCESS` followed by the architectures, application path, icon status, and DMG path.

## 8. Confirm the output files

```bash
ls -lh build
```

You should have a `Wolffe TV.app` bundle and the release DMG.

## 9. Confirm the executable architectures

The build script already validates this automatically, but you can check again manually:

```bash
lipo -archs "build/Wolffe TV.app/Contents/MacOS/WolffeTV"
```

The current Universal build is expected to contain:

```text
arm64 x86_64
```

The order displayed by `lipo` may differ.

## 10. Verify the app's code signature

The build script already performs verification. To repeat it manually:

```bash
codesign --verify --deep --strict --verbose=2 "build/Wolffe TV.app"
```

Remember: the current project uses **ad-hoc signing**, not Developer ID signing/notarization.

## 11. Install from the DMG

Open:

```text
build/Wolffe-TV-v4-alpha3.7-universal.dmg
```

Drag the application into Applications.

## Alpha 4.0A self-hosted server foundation

Opt-in LAN HTTP server, off by default, on port **8765**. The host-only settings show listener status, interfaces, IPv4/IPv6 addresses, Wolffe Host ID, URL, access code, port, and a future authenticated-client limit. `GET /` and `GET /api/status` are the only routes. No TV control or administration endpoint exists yet. The client limit defaults to **1**, is stored now, and will be enforced in Alpha 4.0C. Plain HTTP is for a trusted LAN only; do not expose it to the Internet.
